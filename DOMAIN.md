# Домен taktab.ru

Основной адрес приложения: `https://taktab.ru`. Проект Vercel: `admin-pvz` в аккаунте `sultanhasanovs-projects`. Домены `taktab.ru` и `www.taktab.ru` уже добавлены в этот проект.

## DNS у регистратора

На 20 сентября 2026 в разделе проекта Vercel **Domains → DNS Records** показаны следующие рекомендуемые записи. Их нужно создать в зоне DNS на Рег.ру, поскольку домен использует DNS-серверы Рег.ру. Перед сохранением ещё раз сверьте значения с Vercel:

| Имя | Тип | Значение |
| --- | --- | --- |
| `@` (`taktab.ru`) | `A` | `216.198.79.1` |
| `www` (`www.taktab.ru`) | `CNAME` | `7d662387e6827d2d.vercel-dns-017.com` |

Перед добавлением CNAME удалите все существующие `A` для `www`, в том числе `76.76.21.21` и `95.163.244.138`: CNAME не может сосуществовать с ними. Для `@` удалите старые `A` на эти адреса и оставьте рекомендуемую запись из таблицы. Vercel указывает, что старый адрес `76.76.21.21` продолжит работать, но таблица выше соответствует текущей рекомендации панели. Не меняйте записи почты (`MX`, `TXT`) ради подключения сайта. Альтернатива — передать управление DNS Vercel через `ns1.vercel-dns.com` и `ns2.vercel-dns.com`, но при этом нужно предварительно перенести остальные DNS-записи.

Проверка после обновления DNS: `vercel domains inspect taktab.ru` и `vercel domains inspect www.taktab.ru`. Дождитесь статуса конфигурации и HTTPS в Vercel. В настройках доменов проекта задайте переадресацию `www.taktab.ru` → `taktab.ru`, если нужен один основной адрес.

## Vercel и Supabase

В Vercel заданы `VITE_PUBLIC_APP_URL=https://taktab.ru` для Production и Preview и `PUBLIC_APP_URL=https://taktab.ru` для Production. Они применятся только к новым деплоям. После настройки DNS пересоберите Production без публикации незавершённых локальных изменений.

В проекте Supabase откройте **Authentication → URL Configuration** и задайте:

- **Site URL:** `https://taktab.ru`
- **Redirect URLs:** `https://taktab.ru/register` и `https://taktab.ru/reset`

После этого проверьте регистрацию с подтверждением почты и восстановление пароля. Если Telegram-боты уже подключены, переподключите их в приложении после запуска нового домена: URL существующих вебхуков не меняется автоматически.

При переезде с `admin-pvz.vercel.app` пользователям понадобится войти заново на новом адресе; установленное PWA также нужно открыть или установить с `taktab.ru`.

## Письма с кодом

Отправитель Supabase Auth: `Пункт <no-reply@auth.taktab.ru>` через SMTP Resend. После подтверждения домена в Resend и настройки SMTP откройте **Supabase → Authentication → Emails → Email Templates** и замените два шаблона:

| Шаблон Supabase | Тема | HTML |
| --- | --- | --- |
| **Confirm sign up** | `Код подтверждения — Пункт` | [confirm-signup.html](supabase/email-templates/confirm-signup.html) |
| **Reset password** | `Код для смены пароля — Пункт` | [reset-password.html](supabase/email-templates/reset-password.html) |

В обоих шаблонах `{{ .Token }}` — цифровой код Supabase. Его длину задаёт **Authentication → Providers → Email → Email OTP Length**; по умолчанию в проекте стоит 8, поэтому в письме приходит восьмизначный код. Чтобы код был шестизначным, поставьте там `6` — приложение принимает от 6 до 10 цифр и работает при любой из этих настроек. Скопируйте HTML целиком в редактор шаблона и сохраните. Не заменяйте переменную на пример кода и не оставляйте в этих двух письмах ссылку `{{ .ConfirmationURL }}`: приложение ожидает ввод кода. **Confirm email** в настройках провайдера Email должен быть включён, иначе при регистрации сессия создастся без проверки почты.

После публикации версии приложения с полями для кода проверьте регистрацию нового аккаунта и восстановление пароля существующего. При замене шаблонов и публикации версии выдержите один порядок: сначала опубликуйте приложение с полями для кода, затем переключите шаблоны Supabase. Если шаблоны переключить раньше, текущая опубликованная версия не предложит ввести код.
