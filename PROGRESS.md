# Состояние переезда на прототип

Переписываем приложение по прототипу `Пункт - прототип приложения ПВЗ.html`: телефонная оболочка вместо antd-панели, две роли (владелец и сотрудник), 30 экранов и 38 нижних шторок. Полный план — `~/.claude/plans/nifty-skipping-raccoon.md`.

Документ ведётся руками: прошёл фазу — отметь здесь.

## Как войти в контекст

```bash
npm install
npm run proto     # распаковать прототип в .prototype/ (в git не хранится)
npm run dev       # приложение: /home, /sched, /people, /money, /more; кабинет сотрудника — /me
```

`.prototype/proto.html` — отрендеренная разметка прототипа со всеми инлайновыми стилями: **источник истины по вёрстке**, сверяться с ним при каждом новом экране. `.prototype/proto-logic.js` — 1545 строк логики, состояний и сид-данных; оттуда берутся формулировки, статусы и правила.

Стенд дизайн-системы — `/kit` (открыт без входа, смотреть с телефона).

### Кабинет сотрудника (фаза 6)

По решению владельца проекта собрано до проверки прав: проверки RLS — в конце, **кабинет не открывать сотрудникам, пока не пройдёт `npm run db:rls`**.

- Вход: `App.tsx` читает роль из `organization_members`; сотрудника с любого адреса уводит в `/me`. `/join/:code?` (`screens/Join.tsx`) — вне табов и вне проверки организации: код → вход или регистрация → `accept_employee_invitation` → `/me`. На старой форме входа — «Я сотрудник, у меня код приглашения». При смене пользователя кэш React Query сбрасывается целиком: ключи не содержат пользователя.
- Экраны `screens/me/`: `MeHome` (следующая смена, начать/закрыть через RPC, «не смогу выйти», плитки, ближайшие смены, колокольчик), `MeSchedule` (два месяца, сетка, легенда, смены с напарниками и суммой), `MeMoney` (остаток и цепочка расчёта, вычеты и премии, выплаты), `MeDeductions` (`/me/money/deductions`, шторка `disagree`), `MeProfile`. Данные — `features/me/` (`useMe`, `useMyMonth`, `useMyUpcoming`, `useMyFeed`), считает тот же `calculateSalarySheet`, что у владельца.
- Лента сотрудника: `buildEmployeeFeed` — статусы своих заявок (статус в `refId`, решение снова зажигает бейдж), «Вас поставили на замену», выплаты, удержания. `NotificationsSheet` выбирает ленту по оболочке.
- Приглашения: `services/invitations.ts`, экран `/people/:id/invite` (код, ссылка, «в мессенджер», перевыпуск, отзыв), строка «Пригласить в приложение» в карточке сотрудника.
- Части удержаний: `employeeShare` / `ownerLossOf` в `entities/calculations.ts` (есть части — считаются только они, остаток — убыток владельца; нет частей — целиком на `employeeId`). Учтены в ведомости и в прибыли. Шторка `split` на экране удержания (в прототипе её нет — добавлена сверх 38), история показывает «<Имя> не согласен: …».
- Правки миграций (0012+ ещё нигде не выполнялись, поэтому на месте): **0015** — неверный код возвращает `{ error }` вместо исключения: исключение откатывало запись о неудачной попытке, и лимит на перебор не работал никогда. **0018** — сотрудник читает свою строку `employees` (без этого не видел даже свои точки: `employee_point_read` проверяет подзапросом к `employees`), дни выплат видит вся организация, удержание видно и по старому полю `employee_id` (`deduction_is_mine`), иначе вычет из зарплаты был бы сотруднику невидим. `rls.mjs` обновлён под эти правила и дополнен (43 проверки, в том числе лимит попыток).

- **Шрифт (18.09).** Замер в Playwright показал две ошибки. (1) Вычисленный вес был 600, но вариативный файл `@fontsource-variable` WebKit стенда рисовал любым весом как 400 — `font-semibold` молча не работал, и снимки врали про вес. Переход на статические `@fontsource/ibm-plex-sans` 300–700. (2) Оболочка вообще набиралась системным шрифтом: обёртка antd `.ant-app` задаёт свой `font-family`, и наследование от `body` до экранов не доходило (шторки в портале получали Plex, экраны — нет). Лечится `.kit-root` на корне оболочки. Регрессия — два теста в `typography.spec.ts`: вес проверяется по **ширине** набранного текста, потому что `getComputedStyle` показывает 600 и тогда, когда браузер рисует 400.

### Новый сотрудник (18.09)

`screens/EmployeeNew.tsx` на `/people/new` — мастер `addEmp` из прототипа: ФИО и телефон → точки (выбранный фильтр ПВЗ или единственная точка отмечены заранее) → ставка с итогом. После записи — экран «<Имя> добавлен» с «Пригласить в приложение» (заменяет мастер в истории, «назад» ведёт в список) и «Позже». «Назад» в шапке — шаг назад внутри мастера. ### Замена, расчёт, перенос из старой панели (19.09)

### Фаза 8: десктоп (23.09)

Экраны не дублировались: раскладку меняет кит по `LayoutContext` (`shared/kit/layout.tsx`), который ставит оболочка. Граница — прежняя `MOBILE_QUERY`: всё, что не телефон, получает десктоп; `useIsDesktop()` (≥1024px) решает только ширину сайдбара.

- **Оболочка** (`app/Shell.tsx`, `app/Sidebar.tsx`): сайдбар 248px с пятью разделами и подпунктами активного раздела (`subs` в `tabs.tsx`, подсветка — `subActive`); на 768–1023px — 72px, одни иконки, подпись в `title`. Таб-бар на десктопе не рендерится. Подпункт открывается с глубиной 0 — без стрелки «назад».
- **Топбар** (`kit/Screen.tsx`): `header` слева (без шапки — название раздела), `filters` справа, за ними место под главное действие: `Fab` порталится туда кнопкой «+ Добавить» (`ActionSlot`). Содержимое — по центру, 760px (`wide` — 1120px, так у графика).
- **Стек** (`app/Stack.tsx`): мгновенная смена, без сдвига и жеста. Ключ экрана — `splitGroup()`: адреса одной группы master–detail держат один ключ.
- **Master–detail** (`app/Split.tsx`, ветки в `router.tsx`): «Люди» (весь `/people/*` справа — карточка, расчёт, правка, ставки, приглашение, новый), «Пункты выдачи», «Деньги → Удержания» (`MoneyDesk`, `Money tab="ded"`). ## Инварианты — не ломать

1. **Ключи кэша только из `src/services/queries.ts`.** Расхождение ключей означает двойную загрузку и разъезд данных после первой правки. Запросы — `keys.*`, сброс после записи — префиксы `scope.*` (не литералы `['shifts']`: опечатка в литерале не падает, а молча оставляет старые данные). `queries.test.ts` сверяет каждый префикс с `keys`.
2. **Ни одного hex-литерала вне `src/shared/kit/kit.css`.** Проверка: `rg "#[0-9a-fA-F]{6}" src --glob '!**/kit.css' --glob '!**/styles.css'` (с `**/`, иначе на Windows исключения не срабатывают). Сейчас выдаёт два исключения: `features/schedule/shareImage.ts` (canvas не читает CSS-переменные — вынести палитру в `getComputedStyle`) и `app/StartupRecovery.tsx` (экран восстановления из `2bc62e9` — решить, нужны ли ему цвета инлайном, или перевести на токены).
3. **Базовые стили — только в `@layer base`.** Preflight Tailwind включён; своё правило для элементов (`button`, `svg`…) вне слоя перебьёт утилиты кита.
4. **Шрифт — статический `IBM Plex Sans`** (`@fontsource/ibm-plex-sans`, веса 300–700), не вариативный: вариативный WebKit рисовал одним весом. Новый вес в коде — добавить его `@import` в `kit.css`. Шрифт задан на `body` и повторён на `.kit-root`.
5. **Шторка одна за раз, вложенные пикеры раскрываются внутри формы.** Открытие второй шторки размонтирует первую и выбросит заполненную форму.
6. **Ячейка графика адресуется точкой, днём и местом.** По сотруднику и дню повторное применение графика плодит дубли.
7. **Две нумерации дней недели.** `slot_config.wd` — от понедельника (0), `WeekdayPattern` — dayjs, от воскресенья. Перевод только через `mondayIndex` из `entities/slots.ts`.
8. **Тост после каждой записи.** Шторка закрывается сразу, и без подтверждения непонятно, прошла ли запись.
