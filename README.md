# PVZ Control

Административная панель для владельцев ПВЗ: точки, сотрудники, смены, зарплаты, финансы, удержания WB и Telegram-бот.

## Запуск

```bash
npm install
copy .env.example .env.local
npm run dev
```

Заполните `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` значениями проекта Supabase. В клиенте используется только anon key; service role ключ не используется и не должен попадать в Vercel или браузер. Без этих переменных приложение показывает экран с инструкцией и не работает с данными — демо-режима нет.

## База Supabase

Выполните миграции из `supabase/migrations` по порядку через Supabase CLI или SQL Editor:

| Файл | Что добавляет |
|---|---|
| `202609090001_initial_schema.sql` | Таблицы, связи, RLS, функция `replace_shift` |
| `202609090002_telegram_manual_entry.sql` | Чаты и коды подключения Telegram |
| `202609090003_per_organization_telegram_bots.sql` | Собственный бот на организацию |
| `202609090004_onboarding.sql` | Профили и `create_organization_with_owner` |
| `202609090005_presets_and_workflow.sql` | Пресеты сумм и ставок, обязательная дата удержания |

В Auth включите Email + Password и задайте Redirect URL для адреса приложения.

## Разделы

Все разделы, кроме «Контроль товаров», работают с реальными данными Supabase.

- **Главная** — доход, расходы, зарплаты, налог, прибыль, завершённые смены и убытки по WB за выбранный месяц и ПВЗ. График доходов по дням, блок открытых удержаний и ближайших смен.
- **ПВЗ** — точки, их архив и запомненные суммы со ставками для каждой точки.
- **Сотрудники** — карточки, привязка к точкам и ставка. Новая ставка пишется отдельной строкой `salary_rules`, поэтому прошлые смены считаются по старой.
- **Смены** — одиночные смены и серия по дням недели, статусы (начать, завершить, не вышел), замена через `replace_shift`.
- **Финансы** — доходы и расходы за месяц, категории расходов, автоподстановка запомненных сумм.
- **Зарплаты** — начислено по сменам и ставкам, премии, штрафы, удержания WB на сотруднике, авансы и выплаты, остаток к выплате, закрытие месяца со снимком расчёта.
- **Удержания WB** — создание с привязкой к смене и сотруднику, статусы с историей событий.
- **Настройки** — организация, ставка налога, включение модулей (выключенный скрывается из меню), категории расходов.
- **Telegram** — подключение бота организации и код для `/start`.

## Запоминание сумм

Чтобы не вводить одно и то же каждый месяц, суммы запоминаются для пары «ПВЗ + категория» в таблице `entry_presets`:

- в форме дохода или расхода при выборе категории сумма подставляется автоматически, под полем видно, что именно запомнено;
- сумму можно перебить, и чекбокс «Запомнить новую сумму» перезапишет пресет;
- все пресеты точки видны и правятся в разделе «ПВЗ»;
- то же самое работает в Telegram-боте: он предлагает запомненную сумму кнопкой и спрашивает, запомнить ли новую.

## Ставки

Ставки живут в справочнике `salary_rates` — он редактируется в разделе «Зарплаты» на вкладке «Ставки». В карточке сотрудника ставка выбирается из справочника (или задаётся своей суммой), а выбранная запись фиксируется в `salary_rules` вместе с датой начала действия, поэтому прошлые смены остаются посчитанными по старой ставке.

Дополнительная часовая ставка (`salary_rules.hourly_rate_kopecks`) нужна для неполных выходов. У смены есть режим оплаты `shifts.pay_mode`:

- `FULL` — полная ставка за смену;
- `HALF` — половина ставки;
- `HOURS` — фактические часы × часовая ставка (если она не задана, начисляется обычная ставка за смену).

## Telegram

Выполните миграции 2–3 и добавьте в Vercel серверные переменные `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_TOKEN_ENCRYPTION_KEY` и `PUBLIC_APP_URL`. Ключ шифрования должен содержать не менее 32 случайных символов. Серверные переменные не должны иметь префикс `VITE_` и не попадают в браузер.

В разделе «Telegram» владелец вставляет token собственного бота от BotFather. Сервер проверяет token, шифрует его, сохраняет отдельно от доступных через RLS данных и автоматически регистрирует уникальный webhook. После подключения владелец создаёт одноразовый код и отправляет боту `/start КОД`. Бот добавляет удержания и расходы кнопками, спрашивает ПВЗ и предлагает запомненные суммы.

## Архитектура

- `src/app` — маршрутизация, каркас и контекст организации (выбранный ПВЗ и месяц).
- `src/pages` — экраны, по одному файлу на раздел.
- `src/services` — доступ к Supabase по доменам.
- `src/entities` — типы и чистые расчёты зарплат и сводки.
- `src/shared` — деньги, даты и общие компоненты интерфейса.
- `api/telegram` — серверные функции подключения бота и webhook.
- `supabase/migrations` — PostgreSQL-схема и RLS.

## Синхронизация кабинета WB ПВЗ

В разделе «Настройки» владелец вводит телефон кабинета WB и код подтверждения. После подключения кнопка «Обновить данные WB» загружает доступные владельцу ПВЗ, сотрудников, их привязки к точкам и удержания WB. Сессия WB хранится только на сервере в зашифрованном виде; для шифрования используется `TELEGRAM_TOKEN_ENCRYPTION_KEY`.

Перед первым подключением выполните миграцию `202609090006_wb_sync.sql`. Версию веб-кабинета из заголовка `X-App-Version` можно переопределить серверной переменной `WB_APP_VERSION`.

Для Vercel добавьте те же `VITE_*` переменные окружения и используйте `npm run build`.
